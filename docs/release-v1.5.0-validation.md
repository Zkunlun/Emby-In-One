# V1.5.0 发布验证与风险边界

[项目主页](../README.md) · [更新日志](../Update.md) · [English](en/release-v1.5.0-validation.md)

V1.5.0 引入共享作品身份索引、解除旧每源 5000 条的被动聚合截断，并新增默认关闭的轻量 Movie/Series 全库与增量 Scanner。本页严格区分单元/模拟验收和真实上游/客户端验收。

## 已完成的验证

- Phase 8 相同业务代码的完整 Go 后端 **728 个顶层测试入口**通过；Phase 9 对相同 Go 业务代码重新执行 Build、Go Vet 和选定的 Scanner/被动合并 Race Detector，未运行全项目 Race。
- 管理前端 63/63 项 Vue 模板与接口契约测试通过；JavaScript 语法检查通过。
- 模拟 Emby 上游覆盖跨源权限/身份冲突隔离、超过 5000 候选的被动分页、已映射剧集季集补全、Initial Full/Delta、检查点、来源代次、暂停/停止/恢复、401/403/429、限速与熔断。**模拟结果不等于真实源扫描验证**。
- 实际进程的无网络隔离 HTTP 验证覆盖管理页面、公开系统信息、Scanner 未授权 401 和默认禁用状态。
- AWS-US 按用户批准部署相同 Go 业务代码的开发构建（版本标识 dev-7373aae）；先在独立复制的现有生产 SQLite 上完成 schema 迁移测试，再做停机一致性备份和正式升级。升级后 **173004 条媒体映射、4 条用户记录**保留；数据库 quick_check=ok、Scanner 表初始化成功、全局扫描关闭、没有来源授权或扫描任务、HTTP 管理页面与健康状态正常。
- AWS 约 1GiB 内存，EIO 观测到约 380MiB systemd 内存使用，原 500MiB 服务限额不变。AWS 本机 Vet 因资源压力主动停止，已在其他隔离环境通过相同业务源码的 Vet；不将 AWS 本机 Vet 写为已通过。
- 正式 GitHub Release 工作流会再次独立执行 Go Vet、全库 Go Test、六架构构建和校验和生成；流水线结果须以 GitHub Actions 实际结果为准。

## 尚未完成的真实验收与功能边界

- 用户仍需在真实 Emby 客户端（含第三方播放器）检查单上游库、全局搜索、被动 Episode、媒体版本选择、播放、观看状态和长时间资源使用。
- **没有**对真实 Emby 上游执行主动全量、Delta、Force Full 或 401/429 故障注入。管理员必须先明确开启全局 scanEnabled 和各上游 allowScan，再选择安全的测试上游；服务商限速与封号风险不可忽视。
- Delta 中的 DateCreated fallback 对历史编辑、旧日期导入只能尽力发现；北京时间 05:00 的定时任务不补跑错过的窗口。跨源 TotalRecordCount 在未枚举完全时可能为临时值；全局排序可能代价较高，跨请求不保证固定快照。
- **本版本不提供 A+B 合并虚拟媒体库**，不主动抓取 Season/Episode、封面、播放流或自动执行周期完整对账。

## 升级安全

升级前要一致性备份**当前生产机**的 SQLite（注意 WAL）、配置、用户/Token/密码密钥、原二进制和管理面板文件，切勿从别的机器使用旧数据库覆盖现有映射。升级应同步更新二进制与同版本 Admin HTML/JS；磁盘上的静态面板文件可能优先于内嵌资源。确认 Scanner 保持关闭、已有用户和播放正常后，再逐源批准扫描。仅回滚二进制而不检查新 schema 兼容性是不安全的。

**正式 Release 以 GitHub 的 V1.5.0 tag 及同名资产为准。** AWS 上的 dev-7373aae 是先行部署的相同业务源码开发标识，并不表示已安装正式发行包。
