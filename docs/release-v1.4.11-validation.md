# V1.4.11 发布验证范围

## 更新内容

- 已观看：只有被接受的 `Stopped` 且同版本已确认播放时长达到 90% 才自动标记；`Progress` 仅更新位置，回拖低于阈值后停止不应标记。
- 重复观看：保留历史 `Played=true` 和本轮有效续播位置，完成停止后清空该位置。
- 租约过期：约三分钟租约失效时，根据已确认的最新进度结算，旧租约不能覆盖新会话。
- 媒体列表：本地 UserData 在合并、过滤和最终分页后叠加，保持总数、页内记录及用户状态正确。
- 沿用原有每源 5000 条候选上限、SQLite 映射结构与多版本识别策略。

## 已执行的验证

- `go vet ./...` 通过；Linux 二进制构建通过。
- 初次全量 Go 测试：724 项通过、1 项旧断言失败。旧断言与 V1.4.11 重复观看语义不兼容，已更新并通过专项复测。
- 7 项播放状态、过期租约、分页专项 `go test -race` 通过，未见数据竞争。
- 修正断言后的第二次全量回归因 layerone Runner 连接中断未能完成。**不能将其记录为全量测试成功**；用户明确批准豁免。
- 2026-10-17：相同业务代码构建的候选版已在 DMIT 上成功启动，SQLite 快速完整性检查为 `ok`，本地 API 与 Caddy HTTPS 均返回 200；用户随后确认实机客户端验收通过。

## 升级与已知边界

- 保留 `config/config.yaml`、`data/mappings.db`、Token 文件及 `data/user-password.key`。升级前应保留 SQLite 一致性备份。
- 上游个别登录可能出现 502；这不是本版已确认修复的问题。
- 不涉及新建全库扫描、提高 5000 条候选上限或改变媒体聚合 SQLite 写入模型。
- GitHub Actions 的正式 Release 构建、六架构资产和校验文件须以实际发布工作流执行结果为准。
